### Bugs found and fixed during the session

1. **Playwright reused a foreign dev server.** Another project was on port 3000 and `reuseExistingServer` picked it up — all 18 tests failed on "theme-dog not found". Fixed by pinning e2e to port 3117.
2. **Corner controls covered the tile centre on phones.** With ~70 px tiles, `max(34%, 36px)` hit areas overlapped the middle, so a centre tap re-spun instead of marking (caught by the iPhone/Pixel projects, not desktop). Capped sizes to `min(max(32%,30px),44%)`.
3. **Completion overlay never appeared.** The `useEffect` that delayed the overlay returned a cleanup that cleared its own timer when the effect re-ran. Replaced with derived state (`completed && dismissedGameId !== game.id`) and a CSS `animation-delay` for the entrance.
4. Unrealistic category-rule test (max 2 of a category that is ⅓ of the pool) — rewritten with satisfiable bounds; also a reminder that rejection sampling only suits mild rules.

## Session 5 — Fix: sounds/haptics were never wired (user report)

**User report:** no sounds or haptics on Android.

**Root cause — process failure:** session 3's transform script aborted on an assertion midway, and only the two edits that broke tests were re-applied. Four edits silently never landed: PlayScreen feedback wiring + mute button (so `feedback.ts` was dead code — nothing played), TileArt fit-width, TileDetail full-image, TileCell art centering. Tests/screenshots didn't catch it: `object-cover` looks similar to fit-width in stills, and no test asserted audio.

**Fix:** re-applied all four edits with post-edit verification greps baked into the script. Mute state refactored to `useSyncExternalStore` backed by a listener in `feedback.ts` (React Compiler lint rejects setState-in-effect). Added an instrumented Playwright check that patches `AudioContext`/`navigator.vibrate` and taps tiles: mark = 2 oscillators + 18 ms vibration, unmark = 1 oscillator + 8 ms, mute stops audio (haptics intentionally stay on mute).

**Lesson recorded:** multi-file scripted edits must verify every replacement landed (assert-after, not just assert-before), and behavioral features need at least one behavioral assertion.

Checks: tsc/eslint clean, vitest 45/45, Playwright 18/18, build clean.

## Session 7 — Persistence hardening (user report: game restarts on app switch)

**User report:** swapping apps or closing the phone restarts the game.

**Investigation:** reproduced the exact lifecycle against production with a persistent browser profile (deal, mark, re-spin, fully close the browser, reopen): restore worked perfectly — same card, progress, re-spins, via both direct URL and home. Conclusion: the restarts came from today's **schema-changing deploys** — restore validation _discarded_ saves written by older versions (5×5 `size`-based, then 5×3), so each redeploy looked like a reset on the user's phone.

**Fixes shipped:**

- `migrateGameState()` — legacy `card.size`/`config.cardSize` saves are migrated to columns/rows instead of discarded; migrated shape is re-saved. Discard (with a console.warn) is now only for truly unrecognizable data.
- Flush-on-background: `pagehide` + `visibilitychange(hidden)` re-save current state so an OS tab-kill right after a tap cannot lose the last mutation.
- `navigator.storage.persist()` requested at game start — protects IndexedDB from eviction under storage pressure.
- Home screen **Continue your game** card (theme slug pointer in localStorage) so reopening the installed app at `/` always leads back to the card.

**Rule going forward:** any change to the persisted `GameState` shape must ship with a migration, not a validation discard.

Checks: 47/47 vitest (migration tests), 24/24 Playwright (new continue-from-home test), tsc/eslint/build clean; production kill-and-reopen repro re-run after deploy.
